5. Full Recommendations

Prioritized by impact vs effort. P1 = critical, P2 = important, P3 = nice-to-have.

P1 — Critical
Replace all window.confirm() dialogs
3 locations use browser-native confirm dialogs: add loadport, delete SI, delete Invoice, delete Packing List. These are unstyled, blocking, and break the app's design language. Replace with inline confirmation cards or a styled confirmation modal.
⚡ High impact · Low effort · 3 files
P1 — Critical
Unify Save: "Save All" instead of 6 section saves
Currently each of the 6 sections (General, Nomination, Cargo, SI, Invoice, PL) has its own Save button. Users routinely forget to save sections. Replace with: (1) a sticky "Save All" button at the bottom/top, and (2) an "unsaved changes" indicator on modified sections.
⚡ High impact · Medium effort · ExportBulkingDetail.tsx
P1 — Critical
Add Status Workflow Stepper
The 4-step workflow (Shipment Planning → Nomination → SI Receive → Voyage Operations) is invisible to users. Add a horizontal stepper at the top of the detail page showing completed/current/upcoming steps. The "Advance" button should be next to the stepper, not in a separate status bar.
⚡ High impact · Low effort · CSS + JSX only
P1 — Critical
Add Shipment No. & ETA to List Grid
The list grid is missing the shipment number column (EBS-YYYY-NNN) — users can't identify records without clicking in. Add it as the first column. Also add ETA column sorted by default (soonest first), color-coded: red=overdue, orange=this week, green=future.
⚡ High impact · Low effort · ExportBulkingList.tsx
P1 — Critical
Per-field Validation Errors in Create Modal
Currently all validation errors are concatenated into a single paragraph at the bottom of the form. This makes it hard to identify which field needs fixing. Display inline errors directly below each invalid field immediately after attempting submission.
⚡ Medium impact · Low effort · CreateShipmentModal
P1 — Critical
Show Status History (Audit Trail)
The backend already has /shipments/:id/status-events returning full audit trail. The frontend never calls it. Add a "Status History" sidebar panel on the detail page showing who changed the status and when. This is especially important for compliance.
⚡ High impact · Low effort · API already exists
P2 — Important
Group Nomination Date Fields
The Nomination section shows 12 date-time fields in a flat grid — overwhelming. Group them into 3 logical sub-sections: "Document Dates" (received nom, received SI), "Vessel Schedule" (ETA/ATA/ETB/ATB), and "Loading Operations" (commence, ETC, ATC, TD). Use date inputs instead of datetime-local where time isn't needed.
🔸 Medium impact · Low effort
P2 — Important
Live Search in List (Remove Search Button)
The list page requires clicking a "Search" button to execute the search. Replace with a live search input that debounces after 400ms. The search icon is enough affordance; a separate submit button creates friction and is not standard web UX today.
🔸 Medium impact · Low effort
P2 — Important
Unsaved Changes Navigation Guard
Currently, navigating away from the detail page silently discards all edited but unsaved fields. Add a beforeunload event and a Next.js route change listener that warns the user with an inline banner ("You have unsaved changes") before they leave.
🔸 High impact · Medium effort
P2 — Important
Export Dashboard with KPIs
The export dashboard is currently an empty "coming soon" placeholder. At minimum add: total active shipments KPI cards (by status), a list of upcoming ETAs this week, and quick-action buttons. The backend already has the data; this is a pure frontend addition.
🔸 High impact · Medium effort · dashboard/page.tsx
P2 — Important
Add Remarks Field to General Information
The remarks field exists in the database schema and UpdateExportBulkingShipmentDto, but it's completely missing from the General Information section UI. Add a full-width textarea for remarks in the GeneralSection component.
🔸 Medium impact · Very low effort · 5 lines of code
P2 — Important
Quick Status Filter Pills in Toolbar
Instead of (or in addition to) the column filter dropdown, show clickable status count pills in the toolbar (e.g., "Planning 2 · Nomination 3"). This is much faster for users who want to filter by a single status — one click instead of opening a dropdown, selecting, and closing.
🔸 Medium impact · Low effort
P3 — Enhancement
Link Cargo Lines to Document Lines (SI/Invoice/PL)
The database has cargo_line_id FK in all document line tables (SI lines, invoice lines, packing list lines). The UI never exposes this relationship. Add a dropdown in each document line to select the linked cargo line. This enables auto-fill of description/quantity from the cargo line.
🔹 High impact · High effort
P3 — Enhancement
Document Status Workflow (DRAFT → CONFIRMED)
SI, Invoice, and Packing List all have a status field (currently always "DRAFT"). Add status progression buttons for these sub-documents and visually distinguish DRAFT vs CONFIRMED/SUBMITTED with different badge colors.
🔹 Medium impact · Medium effort
P3 — Enhancement
Keyboard Shortcut: Ctrl+S to Save
Power users editing the detail page will expect Ctrl+S (or Cmd+S) to save. Add a keydown listener to the detail page that triggers "Save All". Also show the shortcut hint in the save button tooltip.
🔹 Medium impact · Very low effort
P3 — Enhancement
Reduce Section Title Size
Section titles in the detail page use var(--typography-fontSize-h3, 24px) which is excessively large for a dense data form. Reduce to 15px with a left border accent (like a tab heading) to maintain hierarchy while reducing visual noise. Already fixed in the improvement mockup above.
🔹 Low impact · 1-line CSS fix
P3 — Enhancement
Remove Dead Import (formatDayMonthYear)
formatDayMonthYear is imported in ExportBulkingDetail.tsx but never used. Remove the dead import. This is a code quality / linting fix — may cause a build warning.
🔹 Code quality · 1-line fix
